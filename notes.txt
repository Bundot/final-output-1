
Step 1 · HTML5 DocType & Boilerplate
index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Tic-Tac-Toe</title>
  <link rel="stylesheet" href="style.css" />
</head>

What?
We are declaring standard HTML5 document metadata, responsive scaling, and linking our external stylesheet.

Where?
In index.html, right at the top inside the <head> tag before any visible UI elements.

How?
By setting <!DOCTYPE html> for standards mode, a viewport meta tag for mobile width parity, and a <link rel="stylesheet">.

Why?
Without DOCTYPE the browser defaults to Quirks Mode, and without the viewport tag mobile screens will zoom out and break touch play.

const WIN_COMBOS = [

  [0, 3, 6], [1, 4, 7], [2, 5, 8], // 3 Columns
  [0, 4, 8], [2, 4, 6]           // 2 Diagonals

JavaScript: Move Handling & Win Evaluation
Step 11 · Event Binding & Click Guard Logic
script.js
cells.forEach(cell => cell.addEventListener("click", onCellClick));
resetRoundBtn.addEventListener("click", resetRound);
resetGameBtn.addEventListener("click", resetGame);

function onCellClick(e) {
  const idx = parseInt(e.target.dataset.index);

  // Guard: Reject move if space is taken or game is over
  if (board[idx] !== "" || !isGameActive) {
    return;
  }

  // Update State array and UI element
  board[idx] = currentPlayer;
  e.target.textContent = currentPlayer;
  e.target.classList.add("taken", currentPlayer.toLowerCase());

  evaluateBoard();
}

What?
We are listening for cell clicks and validating that the chosen tile is empty before applying a move.

Where?
In script.js inside the onCellClick function and cell listener loops.

How?
Reading e.target.dataset.index; early-returning if board[idx] !== ""; then updating both the array and CSS classes.

Why?
Guard clauses prevent overwriting existing moves and stop users from continuing to play after a round has concluded.



Step 12 · Win Check, Draw & Turn Switching
script.js
function evaluateBoard() {
  let won = false;
  let line = [];

  for (const [a, b, c] of WIN_COMBOS) {
    if (board[a] && board[a] === board[b] && board[a] === board[c]) {
      won = true;
      line = [a, b, c];
      break;
    }
  }

  if (won) {
    isGameActive = false;
    line.forEach(i => cells[i].classList.add("win-cell"));
    statusText.textContent = `Player ${currentPlayer} Wins!`;
    currentPlayer === "X" ? scoreXEl.textContent = ++scoreX : scoreOEl.textContent = ++scoreO;
    return;
  }

  if (!board.includes("")) {
    isGameActive = false;
    statusText.textContent = "Round ended in a Draw!";
    scoreTieEl.textContent = ++scoreTies;
    return;
  }

  // Toggle Turn
  currentPlayer = currentPlayer === "X" ? "O" : "X";
  statusText.textContent = `Player ${currentPlayer}'s Turn`;
}

What?
We are testing if the current move completed a line, filled the board without a winner, or passes the turn.

Where?
Inside the evaluateBoard function called at the end of every valid click.

How?
Destructuring [a, b, c] over WIN_COMBOS, halting inputs with isGameActive = false on win/draw, or toggling X and O.

Why?
Checking win patterns before checking for empty slots ensures that a 9th-move win is credited as a victory rather than mistaken for a draw.



Reset Functions & Screen Recording Checklist
Step 13 · Round Reset vs Full Game Reset
script.js
function resetRound() {
  board.fill("");
  isGameActive = true;
  currentPlayer = "X";
  statusText.textContent = "Player X's Turn";
  cells.forEach(cell => {
    cell.textContent = "";
    cell.className = "cell";
  });
}

function resetGame() {
  resetRound();
  scoreX = 0; scoreO = 0; scoreTies = 0;
  scoreXEl.textContent = "0";
  scoreOEl.textContent = "0";
  scoreTieEl.textContent = "0";
}

What?
We are providing a soft reset for consecutive matches and a hard reset that clears scores.

Where?
At the bottom of script.js wired to the two bottom control buttons.

How?
board.fill("") empties board memory, className = "cell" strips styling, and resetGame zeroes the scoreboard numbers.

Why?
Separating round clearing from match score clearing avoids frustrating players who want multi-round competitions without tally loss.
